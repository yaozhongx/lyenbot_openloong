## D001：URDF 数值属性尾部空格

日期：2026-07-14

状态：已解决

### Bug 现象

Lyenbot 原始 URDF 中有少量 XML 数值属性带首尾空格。部分旧版 URDF 解析链可能无法稳定读取对应数值，存在惯量等机械参数被错误解析的风险。

### 影响

Pinocchio 动力学模型可能使用错误或缺失的机械参数；直接编辑 URDF 又违反“原始模型只读”的要求。

### 排查过程

1. 计算并记录原始 URDF SHA-256；
2. 检查 XML 属性内容；
3. 统计需要内存 trim 的属性数量，当前为 4；
4. 分别建立浮动基座和固定基座模型；
5. 检查惯量、质量矩阵和 Frame 是否可正常计算。

### 最终解决方案

`readNormalizedUrdfXml()` 读取完整 XML 后，只在内存字符串中 trim 属性首尾空格，再交给 Pinocchio；不把内容写回原文件。

### 验证结果

- 原始文件 SHA-256 实施前后相同；
- Pinocchio 成功得到 `nq=30`、`nv=29`；
- 活动关节、Frame、限制和动力学量可读取。

### 注意事项

日志 `normalized_attribute_whitespace=4` 是兼容处理计数，不代表 URDF 被修改。

## D002：初始基座高度导致足底穿地

日期：2026-07-14

状态：已解决

### Bug 现象

使用早期假设的基座高度时，Lyenbot 初始足底低于地面约 70.7 mm，仿真开始会出现强烈接触修正。

### 原因分析

旧高度来自其他机器人或人工常量，没有结合 Lyenbot 的 URDF 腿部尺寸、初始屈膝姿态和足底 Frame。

### 排查过程

1. 用 Pinocchio 构造 Lyenbot 初始关节姿态；
2. 计算左右 `left_foot_contact_point/right_foot_contact_point` 世界位置；
3. 反求使足底 `z=0` 的基座高度。

### 最终解决方案

将 Lyenbot 初始基座高度设为由正运动学得到的 `0.850693 m`，并由生成器写入 keyframe。

### 验证结果

Pinocchio 与 MuJoCo 在同一姿态下的左右足底位置误差约 `4.65e-7 m`，PD 站立通过。

## D003：MuJoCo actuator 顺序耦合

日期：2026-07-14

状态：已解决

### Bug 现象

旧接口使用 `mj_data->ctrl[i]` 输出第 `i` 个电机扭矩，默认控制数组顺序和 XML actuator 顺序完全一致。

### 风险

只要 XML actuator 排序变化，正确计算的膝、踝或手臂扭矩就可能施加到错误关节。

### 原因分析

关节反馈已经能够按名称查询，但控制输出仍保留了数字顺序假设。

### 最终解决方案

1. 按配置关节名查找 MuJoCo joint id；
2. 根据 `actuator_trnid` 查找驱动该 joint 的 actuator id；
3. 保存显式映射；
4. 输出到 `ctrl[actuatorId]`。

### 验证结果

23 个配置关节都能找到唯一 joint 和 actuator；静态名称映射检查通过。

### 剩余验证

仍需补充 23 个关节逐一小角度动态扰动测试，确认正方向和实际运动完全对应。

## D004：首帧基座线速度尖峰

日期：2026-07-14

状态：已解决

### Bug 现象

若首次读取时使用“当前基座高度减去初始化为零的旧位置”计算速度，可能产生数百米每秒的虚假线速度。

### 原因分析

旧位置缓存尚未建立，第一次差分不具备物理意义。

### 最终解决方案

首帧 `baseLinVel` 固定为零，同时保存当前 `basePos`；从第二帧开始才做位置差分。

### 验证结果

PD/WBC 启动时不再因首帧虚假速度触发异常控制。

## D005：WBC 双足站立约束漂移

日期：2026-07-14

状态：已解决

### Bug 现象

早期 WBC 能短时接管，但双脚世界位姿会缓慢漂移，约数秒后机器人跌倒。

### 原因分析

站立接触任务只有瞬时速度/加速度约束，没有在进入 WBC 时锁存足底世界位姿并持续纠正离散积分误差。

### 排查过程

1. 比较 PD 与 WBC 接管前后的足端世界坐标；
2. 检查 contact Jacobian 与任务误差；
3. 观察漂移为累积型而非单次映射跳变；
4. 在 WBC 接管时保存当前左右足底位姿作为 anchor。

### 最终解决方案

站立任务以锁存的足底世界位姿构造 `errX/derrX`，持续消除离散漂移；Lyenbot 使用较低刚度和较高阻尼的保守增益。

### 验证结果

第 3 秒 WBC 接管后持续站立 10 秒，最终 `base_z=0.848591 m`。

## D006：GUI 关闭时资源重复释放

日期：2026-07-14

状态：已解决

### Bug 现象

GUI 关闭回调和 demo 主程序都可能释放 `mjModel/mjData`，存在双重释放和退出崩溃风险。

### 原因分析

窗口/渲染资源和物理模型资源的所有权边界不清晰。

### 最终解决方案

- `UIctr` 只负责 GLFW window、MuJoCo scene/context、像素缓存和录像文件；
- demo 主程序独占 `mjModel/mjData`；
- `Close()` 只设置窗口关闭标志；
- 析构顺序保证先释放 GUI，再释放 MuJoCo model/data。

### 验证结果

GUI 相关目标编译通过；无 GUI 的 PD/WBC 回归仍通过。实际桌面环境中的关闭行为仍建议继续观察。

## D007：重复未命名 geom 警告

日期：2026-07-14

状态：待验证

### Bug 现象

MuJoCo 加载派生模型时可能提示：

```text
Geom with duplicate name ''
```

### 原因分析

URDF 导入生成了多个没有名称的 geom。空名称重复不参与当前 joint/actuator 名称映射。

### 当前处理

保留警告，不修改原始 URDF，也不屏蔽加载错误。

### 已知结果

模型生成、一致性检查、PD 和 WBC 站立均可通过。

### 后续验证

需要确认重复 geom 是否导致行走阶段的异常碰撞、接触数量过多或自碰撞问题。

## D008：首步单支撑侧向失稳

日期：2026-07-14

状态：未解决

### Bug 现象

低速 WBC 行走进入首步单脚支撑后，机器人出现明显横向失稳并触发安全停机。没有发现 NaN。

### 已排除

- URDF/Pinocchio/MuJoCo 基本维数一致；
- 23 个 joint/actuator 静态名称映射一致；
- 初始足底位姿一致；
- PD 双足站立通过；
- WBC 双足站立通过。

### 可能原因

- 支撑足完整接触约束或摩擦模型不合适；
- 双支撑向单支撑的质心转移不足；
- 足端轨迹和 Lyenbot 髋宽/足底几何不匹配；
- ankle effort 余量不足或 WBC 权重不合适；
- touch 只有标量法向力，接触信息不完整；
- 支撑足发生滑移；
- AzureLoong 遗留步态常量仍不适合 Lyenbot。

### 下一步排查

1. 实现准静态原地单步；
2. 记录 CoM 投影、支撑多边形、支撑足位姿、接触力和 ankle effort；
3. 分离“双支撑转移失败”和“摆脚轨迹失败”；
4. 小步长、低抬脚、低速度逐项验证；
5. WBC 行走稳定前不进入 MPC 调参。

## D009：`velocimeter` 尚未进入基座速度链路

日期：2026-07-14

状态：待验证

### 现象

MuJoCo XML 已生成 `velocimeter`，`MJ_Interface` 也查询其 id，但当前 `baseLinVel` 实际使用 `basePos` 相邻帧差分。

### 风险

位置差分对仿真步长和数值噪声敏感；同时必须明确 MuJoCo sensor 和 Pinocchio 对速度坐标系的不同约定。

### 后续方案

并行记录位置差分速度与 `velocimeter` 输出，完成坐标系转换后比较误差，再决定替换方式。未经验证不能直接切换。

## D010：足底 touch 不是完整接触 wrench

日期：2026-07-14

状态：部分解决

### 现象

左右 `touch` sensor 各输出一个法向接触力标量，当前写入 `fL[2]`、`fR[2]`，供落地阈值判断。

### 已实现用途

可判断摆动脚是否先离地、后落地，改善步态状态切换。

### 限制

不能由该标量得到切向力、接触力矩或完整 6D wrench，因此不能直接作为严格 WBC 接触力反馈。

### 后续方案

评估 MuJoCo contact force API，或增加适当的 force/torque sensor 建模，并与 WBC 使用的接触 wrench 定义对齐。
