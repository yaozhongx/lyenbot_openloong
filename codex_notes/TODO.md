# 待办任务

## 1. 维护规则

优先级定义：

- `P0`：阻塞当前核心验收，优先处理；
- `P1`：核心功能完成后必须处理；
- `P2`：提高正确性、可维护性或测试覆盖；
- `P3`：依赖外部资料或属于后续阶段。

状态定义：

- `未开始`
- `进行中`
- `暂缓`
- `阻塞`
- `已完成`

任务完成时必须记录验证证据，并在 `CHANGELOG.md` 中增加对应修改记录。

- 目标：逐个给 23 个关节施加安全的小幅位置或扭矩指令，确认 MuJoCo、Pinocchio 和控制数组对应同一名称及正方向。

### P0-2：实现准静态原地单步测试

- 状态：已完成
- 实现：新增 `step-left`（左脚抬落、右脚支撑）和 `step-right`（右脚抬落、左脚支撑），独立执行协调姿态转移、双支撑卸载、原地竖直抬脚、持续触地确认、姿态恢复和落地后 3 秒保持；该路径不调用 GaitScheduler、FootPlacement 或 MPC。
- 自动判据：摆脚离地、touchdown、双足连续稳定时间、支撑足最大水平滑移、最大 roll/pitch；安全停机异常也输出这些指标。
- 复现命令：在 `build/` 中分别运行 `./lyenbot_staged step-left --diagnostic=/tmp/lyenbot_step_left.csv` 和 `./lyenbot_staged step-right --diagnostic=/tmp/lyenbot_step_right.csv`。
- 验证结果：离线可行域扫描证明合法单支撑必须协调调整 base-y、base height 和 roll。采用扫描得到的 `base_z=0.80 m`、支撑侧 roll `0.40 rad` 和脚中心内移 `4 mm` 参考后，两侧均完成释放、腾空、落脚和恢复站立。`step-left` 于 `13.028 s` 确认释放，落地恢复后稳定 `4.870 s`，支撑足最大滑移 `0.064 mm`；`step-right` 于 `13.027 s` 确认释放，稳定 `4.867 s`，最大滑移 `0.062 mm`。两侧均输出 `LYENBOT_SINGLE_STEP_OK`。
- 历史对照：仅横移直立姿态时，加入 URDF 位置目标和越限方向前馈保护后，`step-left/right` 分别于 `14.239/14.247 s` 停止；旧 `14.517/14.494 s` 结果依赖 ankle-roll 软限位穿透，不作为有效基线。
- 目标：不前进，仅完成“双支撑移重心 → 单脚抬起 → 原地落下 → 恢复双支撑”。
- 原因：将单支撑稳定问题与前向落脚规划问题分开。
- 验收条件：
  - 左右脚分别完成一次原地抬落；
  - 单脚支撑期间支撑足不明显滑移；
  - 基座 roll/pitch 不触发安全阈值；
  - 落地后能回到稳定双支撑并保持至少 3 秒。

- 目标：在不改变控制行为的前提下记录首步失败前后的关键状态。
- 必须记录：
  - 仿真时间、步态状态和相位；
  - 基座位置、速度、RPY、角速度；

  - 左右足世界位姿和速度；
  - touch/contact 状态；

  - 支撑足滑移量。
- 验收条件：失败可以通过日志定位到接触切换、轨迹、权重、力矩饱和或滑移中的具体类别。

### P0-4：解决首步单支撑横向失稳

- 状态：已完成（准静态单步范围）
- 关联调试记录：`DEBUG_LOG.md` 的 D008。
- 解决结果：独立离线扫描器在固定双足锚点下联合扫描 base-y、base height 和 roll，并以 IK、URDF 腿部限位、膝最小屈曲和 CoM 支撑范围筛选参考。扫描证明原“保持直立、只横移 CoM”参考不可用，但协调姿态存在合法可行域。将其用于单步后，左右支撑都完成准静态抬落且不触发安全停机，满足本任务验收条件。
- 保留边界：在线一维参考缩放、严格等式 joint-limit 任务、仅捕获点门控和两段卸载均不能形成可用单步，已撤销。当前 `0.40 rad` roll 是独立扫描得到的 Lyenbot 单步验收参考，不应直接复制到连续 walk；正式 walk 仍需把可行参考生成、实测接触切换和关节保护配置化。
- 调试顺序：
  1. 检查支撑足碰撞和摩擦；
  2. 检查双支撑到单支撑的 CoM 横向转移；
  3. 检查支撑多边形与 CoM 投影；
  4. 检查 ankle effort 饱和；
  5. 检查足端轨迹是否使用 Lyenbot Frame/尺寸；
  6. 最后才调整 WBC 权重和步态速度。
- 验收条件：左右支撑都能完成准静态单步，不触发安全停机。
